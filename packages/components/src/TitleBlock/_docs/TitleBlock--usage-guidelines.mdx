### Light (recommended)

<Canvas of={TitleBlockStories.LightVariant} sourceState="hidden" />

**If you're using navigation tabs, set `variant="light"` on each
`NavigationTab`** Tabs don't inherit the variant from the TitleBlock. set
it in both places, or the tabs keep their purple background.

```tsx
<TitleBlock
  variant="light"
  title="Page title"
  navigationTabs={[
    <NavigationTab key="1" variant="light" text="Label" href="#" active />,
    <NavigationTab key="2" variant="light" text="Label" href="#" />,
  ]}
/>
```

## Sticky behavior

Setting `sticky` pins the TitleBlock's top strip to the top of its scroll
container as the page scrolls, instead of letting it scroll away. Full
mechanism, structure, and code for reserving space above the strip (for
example, a banner) are covered in the
[Sticky Banner guide](/docs/components-titleblock-sticky-banner--docs).

**If your surface is adding Coach, turn `sticky` on.** A pinned top strip is a
requirement when the header carries a Coach button.

### Coach button placement

For teams adding Coach to a surface that already has a primary Call to action CTA:

- **Coach is the primary action.** Pass it as `primaryAction`.
- **Demote the existing primary CTA to `defaultAction`.** This is the slot
  that renders immediately to the left of `primaryAction`, in the same top
  row. Don't use `secondaryActions` or `secondaryOverflowMenuItems` for this.
  Those render in a separate row below, alongside the navigation tabs, not
  next to the primary and default actions.

  TitleBlock predates current naming conventions, so `defaultAction` is
  its term for what a modern component would call a secondary action: a
  non-primary button rendered next to the primary one.

- **Coach sits furthest right**, closest to the side panel. TitleBlock is
  props-based and its action slots aren't reorderable, so passing Coach as
  `primaryAction` gives you this placement automatically.

### Default action limitations

`primaryAction` and `defaultAction` both render in the top row, but they don't
accept the same props:

- **`defaultAction` accepts a `badge`.** Pass `badge: { text: '3' }` alongside
  the label. It reaches the underlying button, so you also get its optional
  `variant` and `reversed` fields.
- **`defaultAction` can't be a dropdown.** Only `primaryAction` accepts a menu
  group (`{ label, menuItems }`) and renders a button that opens a menu.
